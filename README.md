# FinanceAgent-LangGraph

A production-grade **multi-agent financial analysis system** built with LangGraph and OpenAI. Input a stock ticker, get back a structured investment report with fundamentals, sentiment, risk metrics, a buy/hold/sell recommendation, and a comparison against Wall Street analyst consensus — all generated by a pipeline of specialized AI agents running on live market data.

**🟢 Live Demo → [financeagent-langgraph-production.up.railway.app](https://financeagent-langgraph-production.up.railway.app/)**

## Architecture

```
User Input (ticker, timeframe, asset_class, thread_id)
        │
        ▼
┌─────────────────┐
│  DataFetchAgent │  ── yfinance → price history, financials, news, analyst consensus
└────────┬────────┘     normalizes recommendationKey → Buy/Hold/Sell
         │
         ▼ (conditional routing by asset_class)
┌─────────────────────┐
│  FundamentalsAgent  │  ── LLM → P/E, EPS, Revenue Growth, Debt/Equity    ┐
├─────────────────────┤     context pruning: 4 keys from 50+ yfinance fields │ parallel
│   SentimentAgent    │  ── LLM → scores headlines → Bullish/Bearish/Neutral │ execution
├─────────────────────┤                                                       │
│     RiskAgent       │  ── pandas → annualized volatility (std × √252)      ┘
└────────┬────────────┘     LLM → risk flag interpretation
         │
         ▼
┌─────────────────┐
│   ReportAgent   │  ── LLM → synthesizes all outputs
└─────────────────┘     compares vs Wall Street consensus → analyst_agreement
        │
        ▼
  Structured JSON Report
```

**Parallel execution:** FundamentalsAgent, SentimentAgent, and RiskAgent run concurrently after DataFetchAgent. Gantt-style benchmarking confirms all three start within 10ms of each other. Conditional routing skips FundamentalsAgent for crypto assets where fundamental data is unavailable.

**Checkpointing:** Every pipeline run is persisted to SQLite via LangGraph's `SqliteSaver`. Each request is identified by a `thread_id` — enabling fault-tolerant resumption and forming the foundation for Human-in-the-Loop (HITL) review.

**State management:** All agents share a typed `FinanceState` (LangGraph `TypedDict`). Each agent reads what it needs and writes back exactly one output.

**Structured outputs:** Every agent uses Pydantic `BaseModel` + `with_structured_output()` — type-safe, validated handoffs. Nullable fields use `Optional[float]` with `default=None` to handle missing yfinance data.

**Error handling:** Custom exception hierarchy (`FinanceAgentError` → `TickerNotFoundError`, `EmptyDataError`, `DataFetchRateLimitError`, `LLMStructuredOutputError`). FastAPI returns 422 for invalid inputs, 400 for pipeline errors, 500 for unexpected failures.

## Performance Benchmarks

Benchmarked sequential vs parallel execution across 5 S&P 500 tickers using instrumented Gantt-style timing (`benchmark.py`):

| Metric | Sequential | Parallel |
|--------|-----------|---------|
| Average latency | 8.99s | 8.17s |
| Min | 7.62s | 5.17s |
| Max | 11.20s | 10.44s |
| Improvement | — | **9%** |

**Finding:** Parallel execution reduces analysis-phase latency by ~30% (Fundamentals + Sentiment + Risk agents all start within 10ms). Overall wall-clock improvement is 9% because ReportAgent (avg 5.6s) dominates total time and runs sequentially by design — it depends on all three agents completing first. This is a direct consequence of Amdahl's Law: with ~63% of pipeline time in an irreducible sequential step, theoretical maximum speedup is capped at ~1.6x regardless of parallelism gains upstream.

## Key Design Decisions

**Tiered LLM strategy** — GPT-4.1-nano for the three parallel analysis agents (fast, cheap), GPT-4.1-mini for ReportAgent (quality matters for final synthesis). Minimizes cost without sacrificing report quality.

**Parallel over sequential for analysis agents** — FundamentalsAgent, SentimentAgent, and RiskAgent have no data dependencies between them. Benchmarked concurrent execution confirms overlap; Amdahl's Law explains why wall-clock improvement is bounded by ReportAgent.

**Checkpointing with thread_id** — SqliteSaver persists full pipeline state after every node. Enables fault-tolerant retries and is the prerequisite for HITL review (Day 4). TTL-based cleanup (7-day retention) runs on every server startup to prevent unbounded DB growth.

**Volatility computed in code** — deterministic pandas formula (std × √252) beats LLM estimation for numerical accuracy.

**Context pruning** — FundamentalsAgent extracts 4 relevant keys from 50+ yfinance fields, saving ~800 tokens per request.

**Optional Pydantic fields** — prevents schema validation crashes when yfinance returns `None` for obscure tickers.

**Custom exception hierarchy** — maps known failure modes to meaningful HTTP responses; unknown failures return 500 with internal logging only.

**Normalized analyst consensus** — yfinance `recommendationKey` values (`strongBuy`, `underperform`) normalized to `Buy/Hold/Sell` for clean LLM comparison.
